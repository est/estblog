[Python]让Last.FM显示歌词、发送正在播放的歌曲到GTalk和MSN状态[附LastFMProxy使用教程]

* 没法暂停
* 没有全局静音热键，有的时候需要听一下其他程序的声音都没办法
* 没法显示歌词。。我要学外语啊。。。没歌词真要命啊。。。

那么我们自己动手丰衣足食嘛

首先有一个非常牛B的开源项目：LastFMProxy

为什么说很牛B呢？因为40多KB的Python程序就实现了一个完整 的LastFM客户端

界面虽然是Web方式，但是功能一个不少，一点不含糊啊，连唱片cover都有。

LastFMProxy的工作原理是：模拟LastFM客户端请求服务器，然后获取mp3字节流然后在本机上建立一个微型http服务器，这样，你就可以通过任何你喜欢的第三方媒体播放器来收听LastFM的音乐了。由于Python是跨平台的，所以LastFMProxy可以完美在Windows，Linux，Mac OS X上运行，甚至支持Python的PPC上都可以！（开放接口、开源的好处啊：Free Labour）

使用很简单，首先用记事本等文本编辑器编辑config.py，把你的LastFM用户名和密码填到对应位置，双击main.py即可。管理方式是Web，在浏览器打开http://localhost:1881/就行了。

用你自己喜欢的媒体播放器打开http://localhost:1881/lastfm.m3u就可以听歌了。

实际上，直接从LastFM服务器请求返回的.mp3是非常原始的，没有任何ID3 tag信息，需要自己DIY才能加上ID3信息。

我知道在这里解释过多的代码是没有用的。这里下载main.py覆盖同名文件就可以了。

我当时研究这个还是比较痛苦的，因为mp3是字节流存在于内存里的，而且mp3是二进制格式。这是我第一次和字节、位、struct之类的东西打交道，很囧。其中有一个synchsafe integers算法：

def dec2sstr(n): """algorithm for ID3v2 header size""" r = (n << 1) - (n & 127) r = (r << 1) - (r && 32767) r = (r << 1) - (r && 8388607) r = (r << 1) - (r && 2147483647) return struct.pack("!l", r)

我自己觉得还是很囧的。这几行简单代码我想了3个小时。。。。笨啊笨。。。

est自己DIY的这个MODDING版本当然还是有bug的，研究这个东西的时候，需要涉及到HTTP mp3 Streaming的一些知识，但是很囧的是，.mp3的ID3metadata头本来就是个 de facto 标准，ID3 v1把东西粘到mp3文件尾部直接造成不可steaming，v2吧放到头部，但是也有问题。就例如LastFMProxy这样的微型服务器，多个mp3文件是当成一个不间断的留输出的，WMP播放的时候，第一次读取了ID3，可是第二次换歌了之后ID3信息居然不刷新，永久停留在第一首歌。。。囧啊囧

我的临时解决办法是：在播放列表里重复一次mp3请求，也就是：

`

EXTM3U

http://localhost:1881/lastfm.mp3
http://localhost:1881/lastfm.mp3
`

也就是说，你不能用LastFM Web界面来skip歌曲了，直接用播放器的“下一首”功能即可。

说说歌词。歌词可以试试WMP的歌词插件：Minilyrics。当然WINAMP和foobar2000的歌词插件是一打一打的。

GTalk和MSN状态就简单了，只要WMP在放歌，GTalk和MSN都会自动改变status。很有意思。呵呵

目前还在研究HTTP的2个流媒体服务协议Icecast和Shoutcast有没有解决办法。其实这也是2个de facto的Live HTTP Streaming协议

最后，要严重鄙视一下微软同学，万恶的Windows Live Messenger居然拒绝在我的Server 2008上安装。。。当然我直接找了个便携版本用上了。当然这样安装的WLM没法和WMP同步正在播放歌曲列表的。当然我也找到了解决办法。启用Windows Media Player插件的方法是：在WLM安装目录运行：regsvr32 psmsong.8.5.1302.1018.dll
